# Android prayer notifications

The notification hook schedules the five prayers (Fajr, Dhuhr, Asr, Maghrib, and Isha) for the remaining prayers today and the seven following local Gregorian dates. Sunrise is excluded. It calculates each date with the current coordinates and prayer settings on the device, schedules only future instants, and refreshes the app-owned reminders when the app resumes or when location, prayer method, language, enabled state, sound, or phone timezone changes. It never requests location or notification permission by itself. It waits for persisted settings/location hydration (`ready: true`) before reconciling; while foregrounded, it re-arms one timer for each local midnight rather than polling.

Integrate `usePrayerNotifications` from `src/use-prayer-notifications.ts` with the settings state. Pass `ready`, `enabled`, the current coordinates or `null`, prayer settings, language, and translated `labels` (`title`, `channelName`, and a `body(prayer)` function). Optional `testTitle` and `testBody` provide text for the user-triggered sound test. Call `requestPermission()` only in the user's explicit enable action, then persist enabled state. The hook reports `status`, `scheduledCount`, `error`, and `timing`, and exposes `reconcile()`, `openExactAlarmSettings()`, `openAppSettings()`, and `testAlert()`. Call `testAlert()` only from an explicit user action; it schedules one test notification five seconds later on the same channel and sound. `status` also reports `channel-muted` when Android has disabled the channel or its sound. Android `timing` is `exact` when the read-only native exact-alarm permission check succeeds, or `may-be-delayed` when Android will use its inexact fallback.

The app registers these config plugins in `app.json`: `expo-notifications` with `assets/adhan/adhan.ogg` and a white notification icon, and `./plugins/withPrayerExactAlarm.cjs` for `SCHEDULE_EXACT_ALARM`. The custom plugin deliberately does not declare `USE_EXACT_ALARM`, which is Play-policy restricted. Expo Notifications adds its reboot receiver and boot permission; scheduled local notifications are restored after device reboot by the library.

For a custom Adhan notification sound, pass the registered filename to the hook's `sound` option and list the file under `expo-notifications`'s `sounds` plugin option. Android notification channels are immutable after creation, so sound changes use a distinct channel ID. OS notification-channel settings, Do Not Disturb, volume, and vendor battery policies remain in control. A notification sound is played as an Android channel sound; the app cannot promise the entire recording will play. Verify the selected recording on a real device and keep the filename/format consistent with the plugin configuration.

The hook installs an Android foreground handler that shows notifications in the banner/list and allows the configured sound. The hook owns only notifications whose `content.data.namespace` equals `quran-adhan-qibla.prayer.v1`; it cancels and replaces those entries without touching other scheduled notifications. The inexact fallback can be delayed by Android, so the UI must not describe timing as guaranteed. The Alarms & reminders action opens Android's exact-alarm access page; the hook rechecks timing when the app resumes. The app notification settings helper opens the notification settings page with an app-details fallback.



## Using the feature

Open the gear sheet, select Adhan, and enable Play Adhan at prayer times. Notification permission is requested at this explicit action. If needed, use the location action to choose a city/device/map/coordinates and the Alarms and reminders action to grant exact-alarm special access. The test button schedules the bundled CC0 Adhan recording five seconds later. Settings and the selected location are restored across launches; no background GPS permission is needed. Open the app at least weekly to replenish scheduled dates.

Turning the setting off cancels pending app-owned prayer/test alerts. Revoked notification access or missing location removes pending app-owned reminders. Clock/timezone changes are reconciled on the next app resume; physical-device reboot, OEM battery policy, DND and complete recording playback require device validation.

If recalculation fails (for example, an unsupported polar location), known previous app-owned alerts are cancelled so the previous city's times cannot continue sounding. Android force-stop disables scheduled work until the app is reopened; launch reconciliation restores reminders from the saved settings and location.
