# Quran recitation audio

Playback is implemented in `src/use-quran-audio.ts` with Expo Audio. Audio files are not bundled with the app. Each ayah is streamed from the corresponding official EveryAyah directory and is downloaded to the app-private document directory only when a user explicitly requests an offline surah copy. The files are not exported, shared, or included in app releases.

The three selectable directories are the recitations listed by EveryAyah: `Alafasy_128kbps`, `Husary_128kbps`, and `Abdurrahmaan_As-Sudais_64kbps`. The source URLs use the official ayah filename scheme, six digits (three-digit surah + three-digit ayah), followed by `.mp3`; for example `001001.mp3`. The EveryAyah listing currently exposes the Alafasy, Husary, and As-Sudais collections and their bitrates at [recitations by ayah](https://www.everyayah.com/recitations_ayat.html); directories are hosted at [everyayah.com/data](https://everyayah.com/data/).

EveryAyah's directory and index pages identify the reciter and bitrate but do not state a reuse license for the individual recordings. Therefore this app does not claim a redistribution license, bundle the recordings, mirror them, or publish them as app assets. It streams from the source and saves user-requested copies only in that user's private app storage for offline playback. Availability, bitrate, network access, and the source's terms may change; playback and downloads can fail if a source file is missing or the host is unavailable. Users should consult EveryAyah and the rights holder for any redistribution or public reuse.

The hook supports selecting a reciter, playback speeds 0.75×–2× with pitch correction, seek ± seconds, previous/next ayah, automatic ayah advance, a looping single-ayah or same-surah range, and Android/iOS background and lock-screen playback. Surah downloads are sequential, with progress, cancellation, completed-ayah preservation, and retry that skips already downloaded ayahs. Each ayah request has a 60-second deadline; a timed-out request cancels the native transfer, removes its partial file, and reports a retryable download error. The app only accepts HTTP 200 responses with an `audio/mpeg` or `application/octet-stream` content type and a nonempty downloaded file. A surah is marked complete only after every ayah file has succeeded; partial files are ignored and removed before retry. Reciter, speed, repeat range, and per-reciter completed-download manifests are stored locally. Downloaded files are scoped by reciter, so changing reciters cannot mistake one reciter's local files for another's. Network state is read from Expo Network and does not trigger a network request during app startup.

Expo app configuration must enable `expo-audio` background playback (`enableBackgroundPlayback: true`); lock-screen playback also requires the audio mode to use `interruptionMode: 'doNotMix'`. The Expo Audio setup and API are documented in [Expo SDK 57 Audio](https://docs.expo.dev/versions/v57.0.0/sdk/audio/).
