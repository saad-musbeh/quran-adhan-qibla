# Adhkar and reminders

Version 0.6.0 adds **أذكار وأدعية** as the fourth main tab. Its three fixed books are morning adhkar (24 entries), evening adhkar (22), and after-prayer supplications (8). All text is Arabic and bundled offline. Reading uses a scrolling list; each entry has an info button for its original reference. After-prayer content is opened manually and does not infer that someone has finished praying.

## Text source

The source is *حصن المسلم* by سعيد بن علي بن وهف القحطاني, digitized by Abdellah SELLAM in [HisnElMuslim](https://github.com/asellam/HisnElMuslim/tree/872764ca013116c905f7fc9c3dc972c27cd37d4a), commit `872764ca013116c905f7fc9c3dc972c27cd37d4a`, under MIT. The upstream describes a transcription from the Dar al-Sijillat printed edition, compared with another electronic copy. This is source provenance, not a new scholarly authentication claim.

Arabic text, repetitions and references are retained; only literal escaped line breaks are converted to actual line breaks. Passages with multiple instructions keep those instructions together. A counter counts the complete sourced passage, including its internal repetitions. Quran verses inside the collection remain Arabic; no verse translations are added.

`src/data/adhkar-manifest.json` records the input/output SHA-256 values and collection sizes. `assets/licenses/HisnElMuslim-MIT.txt` and runtime Credits retain the full licence. Reproduce with `python3 scripts/import-adhkar.py`.

## Reminders

The bell in this tab and Settings → Reminders open the same controls. All recurring reminders start **off**. Enabling one asks for notification permission only in that explicit action.

- **الصلاة على النبي:** a daily start/end window and repeat interval (20 or 30 minutes, one, two or three hours). Fresh preferences use 8 AM–8 PM every 30 minutes, still disabled until enabled. Existing chosen-time schedules are retained. The schedule dialog has Save/Cancel and 12-hour time wheels. The phrase dialog previews and saves a recorded phrase; “صلِّ على رسول الله” is the default. Sound can be switched off independently.
- **Morning/evening:** independent daily times; tapping their notifications opens the corresponding collection, including after a cold launch.
- **After prayer:** a reading collection, without automatic after-prayer alerts.

The five spoken options are trimmed recorded excerpts from the user-provided `134122.mp4` reference, replacing the former eSpeak voice. Arabic options are “صلِّ على رسول الله”, “صلى الله عليه وسلم”, “صلِّ على النبي”, and “اللهم صلِّ على محمد”; the English option is “Peace be upon him”. Source ranges, hashes and processing are in `assets/adhan/salawat-phrases-manifest.json`. No public redistribution licence was supplied for these reference recordings; they are not claimed as CC0 or covered by the code MIT licence. The alternative chime is generated by this project. These sounds are bundled, so scheduled notifications need no network or running JavaScript. Notification volume, Silent Mode/Focus, Android battery rules and alarm access still govern delivery. No background location is requested.

The separate `quran-adhan-qibla.devotional.v1` namespace keeps reminder changes from cancelling prayer alerts. Daily reminders use native repeating local-time triggers. The app reconciles them at launch, resume, local midnight, and preference/language/location/timezone changes. Interval schedules allow up to 48 Salawat slots plus two morning/evening slots. Invalid, overnight or larger windows are rejected in full. On iOS, Adhan uses the remaining space within 62 requests, reserving two test slots; up to 40 upcoming prayers are retained, or at least 12 with the densest valid reminder window. Open the app daily when using frequent reminders to refresh Adhan. Android retains its normal eight-date prayer horizon. Both scheduling families reconcile serially to avoid racing the iOS pending-request limit.

## Testing settings

Settings → Extra testing settings contains four saved switches:

- Adhkar counters, with session completion and reset.
- One dhikr at a time, with Previous/Next controls.
- Reminder styles: spoken, silent text, or chime and text.
- Schedule mode selection: retained chosen times, normal daytime intervals, or experimental prayer-linked reminders.

Turning testing switches off hides tone selection and prayer-linked schedules. The normal sound switch, saved phrase and daytime interval remain available; a prayer-linked schedule falls back to a daytime interval. Interval windows do not cross midnight; invalid or over-capacity windows show an error. Prayer-linked tests use the same Rust calculations and location as Adhan, schedule the nearest available requests, and need a daily app visit to refresh. Missing location/calculation does not remove separately enabled morning/evening reminders. Counters are per reading session; they reset when opening a collection or using Start again.

New interface copy is complete in Arabic and English. The other 38 opt-in testing locales retain their existing translations and show English fallbacks for new 0.6.0 labels pending review; the translation service returned HTTP 429 during preparation.

Reference-style dialog checks cover 32 Arabic/English, light/dark, normal/large-text phone/tablet layouts with the actual React components in a web harness (native audio and icons substituted). Save/Cancel, invalid-window blocking and saved phrase selection passed. A host simulation of both real scheduling hooks passed six sparse/dense/off transitions and concurrent sound tests without exceeding 64 pending iOS requests (50 devotional + 12 Adhan + 2 tests at maximum density). `npm run check` passed 150 host behavior/asset tests and 17 Rust tests; both mobile exports passed. The Android release build passed. The local API 36 emulator exited with a segmentation fault (139) before registering with ADB, so native iOS playback and physical-phone notification delivery still require verification.

## Collection title layout follow-up

The user reported clipped Arabic collection titles on a TECNO POVA 7 5G / TECNO LJ7 (1080 × 2460). Card labels now use the full inner card width, do not shrink vertically, retain font padding, have an explicit scalable line height and writing direction, and use simple Android line breaking. Labels remain centered and can wrap as text grows. The change is local to collection cards.

The actual component passed 60 web-harness variants across five phone/tablet and landscape viewports, Arabic/English, light/dark and text scales 1, 1.45 and 2. All three complete labels remained inside their cards; opening each collection passed. `npm run check`, both mobile exports and the Android release build passed. The ARM64 APK audit verified 604 offline Quran pages, 12 notification sounds and no iOS WAV resources. Physical TECNO rendering and playback remain unverified; the browser harness substitutes native audio, fonts and icons.
